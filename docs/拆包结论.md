# 拆包结论：从《苏丹的游戏》和《邪教模拟器》看黄昏之门

拆源：H:\SteamLibrary\steamapps\common\ 下四本。
结论：真正能直接读设计数据的只有《苏丹的游戏》，其余内容都编译进了 Unity 资源。

## 一、《苏丹的游戏》（Sultan's Game）
- `Sultan's Game_Data\StreamingAssets\config\*.json` 全裸可读，带中文注释。
- 核心模型：**人物卡 + 标签 + 仪式槽位**。
- 标签表 `tag.json` 就是它整个资源系统，分两类：
  - buff（可加可减的属性）：体魄 / 魅力 / 智慧 / 隐匿 / 战斗 / 社交 / 学识 / 生存 / 魔力 / 影响力 / 污名 / **价值(money)** / 不满。
  - attribute（身份/归属/状态）：已拥有 / 地点 / 人类 / 恶名 / 男性 …（还有女性、苏丹等）。
- 卡带状态 `card_state`：受伤 hurt / 染欲 traces_of_desire / 受诅 cursed / 染病 sick / 被献祭 sacrifices。
- 循环：抽卡 → 放进「仪式」结算 → 卡受伤、染欲、被献祭 → 产出新卡和标签。
- 它没有「血条」，只有一堆卡和卡上的标签。金钱是一张「价值」标签，不是数字。

## 二、《邪教模拟器》（Cultist Simulator）
- 内容编译进 Unity 资源，拆不动；但 `StreamingAssets\MODDING_README.txt` 把整套循环写白了。
- 词汇：卡＝**元素**（健康/激情/理性/金钱/密传/道具/人物）；动作＝**动词**（时间流逝/工作/研究/入梦/谈话）；标签＝**相性**（灯/铸/杯/启/蛾/冬…）；**配方**＝输入卡变输出卡；**传承**＝开局身份；**终局**＝结局。
- 连「时间」本身都是一个动词槽位：往「时间流逝」里塞钱，出的是钱生钱的活法；塞密传，出的是狂人的活法。

## 三、对黄昏之门的改法
上一版的「钱 / 口碑 / 时辰」三个裸数字，像三条血条。照这两本改成卡：

1. **死者是一张卡**，不是一行字。标签如：孤老 / 横死 / 无主 / 大寿 / 横财 / 有仇家 / 官面上的人 / 教内的人。
2. **五步（收尸/洗身/穿衣/念辞/出殡）是五个槽位**。每一步的选择不直接改三个数字，而是改死者卡上的标签，最后结算时按标签折算产出。
3. **钱和口碑不裸奔**：钱是「价值」标签，口碑是「信任」标签，都挂在街坊、同业、官方这几张「关系卡」上。时辰是「时间」动词，一天几格，每步花格。
4. **密教层照抄相性**：Eidos、无限、Ω、壹祖、安乐死是五张「供奉卡」。每单可以把死者的一部分标签「献祭」给某个供奉，换密传卡；密传攒够了触发该派的结局。

## 落地顺序
- 先把 `F:\job\oc-game\src\js\funeral.js` 的 `CHOICES` 从「改三数字」改成「改死者卡标签 + 花时辰 + 结算折产出」。
- 关系卡（街坊/同业/官方）和供奉卡先做骨架，各一张，能跑通一轮再扩。

# 第二部分：炼金模拟器 / 夜雀食堂 / 火山的女儿 / 頭七

拆源：H:\SteamLibrary\steamapps\common\ 下四本。可读性结论：只有《火山的女儿》有明文数据，
其余内容都编译进了 Unity（Addressables / il2cpp），拆不动。所以下面四条是「设计结论」，不是「拆包抄到的数值」。

## 各本可读情况
- **火山的女儿**：`VolcanoPrincess_Data\StreamingAssets\dataConfig\txt`（5.4MB）是四语字符串表，明文，可读。
  内容关键字：火山国 / 女儿养成 / 课程 / 工作 / 研究 / 料理 / 剧场 / 祭坛 / 好感度 / 多结局。
  其余 `data`/`explo`/`world` 是自定义二进制（控制符分隔 + 数字 ID），无 schema，不值当逆向。
- **药剂工艺：炼金模拟器**：`StreamingAssets\aa\catalog.json` 只是 Addressables 登记表（m_InternalIds 那套），无设计数据。
- **东方夜雀食堂**：il2cpp 打包，`StreamingAssets` 里只有音乐工具，无明文。
- **頭七**：`Asset\data\*.bin` 是二进制游戏数据，`filemap.bin` 只是 CDN mp3 地址表；`Asset\script\engine.cg` 是引擎脚本。

## 对黄昏之门的四条结论
1. **工序要有手感**（炼金模拟器）：它的乐趣是亲手研磨、倒水、搅拌、加热，材料在地图上有路径，配方要自己试出来。
   → 殡仪馆的收尸/洗身/穿衣/念辞/出殡不该是点按钮，每道工序要有可操作内容：洗身选水温和手法，穿衣选寿衣，念辞选词。
   而且「讲究」要试出来，不是摊开给你看的配方。
2. **口碑 = 回头率**（夜雀食堂）：顾客带着口味和好感来，重复光顾，好感解锁剧情和食谱。
   → 街坊是回头客。接单不是一锤子买卖，做得好人家会再来、会带亲戚来。口碑不叫「信任点数」，叫「下次还会不会有人上门」。
3. **时辰 = 日程格**（火山的女儿）：日程表是核心资源，每天几个格子排课程、工作、探索，数值养成，多结局。
   → 时辰就是日程格，一天几格排工序和走关系。多结局照搬：守成本分 / 投靠某派 / 被曝光，三种店的下场。
4. **七日是时间锚点**（頭七）：头七、做七，七日一个轮回，仪式有固定时间结构。
   → 殡仪馆天然有「七日」：人死后第七天回魂，做七是节点，做成周期性事件，让玩家有节拍，不是无限流水线。

# 第三部分：脑叶公司 / 犹格索托斯的庭院 / 頭七（真实拆包结果）

## 脑叶公司（LobotomyCorp）——真的拆开了
`LobotomyCorp_Data\ExternalData\xml\Language\` 全是明文 XML，这是四本里最有价值的参考。

- `creatures\` 有 **101 个异想体**，每个是一份 XML。
- 危险等级五档，实测分布：ZAYIN 12 / TETH 26 / HE 32 / WAW 28 / ALEPH 12。
- 工作方式四种：`Skills_cn.xml` 明写 **本能 / 洞察 / 沟通 / 压迫**，另有工具型异想体的特殊工作（请求 / 赎罪 / 演奏）。
- 每个异想体有情绪条 `feeling`：好 / 普通 / 坏 → 能量产出 +0.5 / +0.3 / -1.3。工作方式不对，情绪就掉。
- 信息是「观察」出来的：`<desc id openLevel>` 按观察等级解锁，越查越知道它是什么，不是开局全摊开。
- 有 `narration` 分动作（move / start / mid1 / mid2 / mid3），给「工作」过程配氛围文案。
- `SefiraDesc`：10 个部门主管，各自就四类事件（员工恐慌 / 员工死亡 / 异想体突破收容 / 部门全灭）向你汇报，台词随阶段升级。
- 员工四维属性（强韧/谨慎/节制/正义）不在 cn XML 里，对应关系是惯例（本能=强韧、洞察=谨慎、沟通=节制、压迫=正义），这点是常识补的，不硬说成拆出来的。

对黄昏之门的直接映射：死者＝异想体（有危险等级、有情绪、有要观察才解锁的真相）；工序＝四种安抚方式（不是点五步按钮）；员工＝雇来的人，带属性派活；突破收容＝尸变闹鬼，要镇压或安抚；部门主管＝街坊/同业/官方，出事了会来问你话。

## 犹格索托斯的庭院（Yog-Sothoth's Yard）——拆不开
il2cpp 打包（`GameAssembly.dll`，无托管 DLL），`StreamingAssets` 全是 FMOD 音频 `.bank`（Favor/Master/Plot/Story/UI…），游戏数据编译进二进制。没有明文配置。设计我不再猜，等有玩家测评或你指方向。

## 頭七——拆不开，但不是没查
- `Asset\data\data*.bin` 头部是 `ID3`，是改名的 MP3（语音/音频），不是游戏数据。
- `Config.bin`（1399 字节）和 `script\engine.cg`（794KB）是加密/编译的二进制，可打印串全是乱码。
- 结论：文字脚本在加密二进制里，没 RE 拿不到。这一点是实测，不是猜。
