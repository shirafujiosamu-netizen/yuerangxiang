## 4. 发现的问题

### 问题 1（轻微 / 表现层）：赌场结算后结果框样式全部失效

- 位置：`src/js/ui.js:201`
- 根因：`'<div id="casino-result' + (this.casino.resultCls ? ' ' + this.casino.resultCls : '') + '">'` —— class 被拼进了 id 属性，结算后实际 id 变成 `casino-result win/lose`（含空格）。
- 现象：`document.getElementById('casino-result')` 返回 null；CSS `#casino-result`（等宽字体 14px 基础样式）与 `#casino-result.win/.lose`（胜绿 #4a7a5a / 负红 --danger）**全部失配**。结果文案仍正常显示，但开局后退化为无样式正文，胜负无颜色区分。
- 取证：复测 DOM 探测 `id="casino-result lose" hasSpace=true`、计算样式 `font-family="Segoe UI"`（非 mono）、`color=rgb(200,205,214)`（非胜负色）。见 `v1_casino_result_bug.png`。
- 最小修复建议：改为 `'<div id="casino-result" class="' + (this.casino.resultCls || '') + '">'`。
- 影响评估：纯样式，不影响任何数值与流程。

### 问题 2（轻微 / 表现层）：赌场结算台词被重渲染吞掉，玩家永远看不到

- 位置：`src/js/ui.js` onDeal 的 setTimeout 回调（约 241-248 行）
- 根因：回调内先 `eidosSay(结算台词)` 再 `renderCasino()`，而 renderCasino 重建的 DOM 中 `#eidos-line` 固定为「赔率永远公平。」，结算台词被同一任务内的重渲染覆盖。
- 现象：洗牌期台词「这一局，开始。」可见（调用在重渲染之后），但「你赢了。完美地。」/「你输了。也完美地。」（含「存在」档 demo 台词）结算后瞬间被吞，玩家只能看到默认台词。dev_notes 4.3 称 fake-DOM 覆盖了「庄家台词」，真实浏览器下该链路不成立。
- 取证：`v1_casino_result_bug.png`（结算后 Eidos 线为默认台词）；探测：洗牌期=「这一局，开始。」→ 结算后=「赔率永远公平。」
- 最小修复建议：把结算台词存入 `this.casino.eidosLine`，renderCasino 渲染时输出；或把 `renderCasino()` 调用移到 `eidosSay()` 之前。
- 影响评估：纯风味文案，无数值/流程影响。

### 非问题观察（记录在案，不计问题）

- 离线弹窗出现的第 1 秒内 HUD 仍显示补算前旧值（main.js 中 renderAll 先于 applyOffline 执行），1 秒后的 tick 自动纠正（实测关弹窗后 HUD 已显示 685）。可接受的渲染时序。
