# 店主视角改造设计（owner_design）

> 2026-10-23 立。缘起：用户问「和犹格索托斯的庭院 / 火山的女儿 / 东方夜雀食堂像嘛」——
> 四作骨架对照结论：框架像（单场景容器+事件+资源+角色），**视角错位**（三标杆玩家是管理者，当前 demo 玩家是赌客）、
> **无循环只有赌局**、**内容量差一个量级**。本文档定义改造方向。
> 原则：赌桌内核与 UI 全部保留，从「玩家动作」重新定位为「营业内容」。

## 一、视角转换定义

| 角色 | 当前 demo | 改造后 |
|---|---|---|
| 玩家 | 赌客（进来就赌，赌完就走） | **店主**（经营赌场，可亲自下场） |
| Eidos | 陪玩钩子 / 关系值对象 | **看板娘兼发牌人**，关系值驱动 buff |
| 闹事 NPC | 事件池角色 | **客人**（场子里的赌客，闹事是经营事故） |
| 五张赌桌 | 玩家操作对象 | **设施**（可开放给客人，也可亲自下场） |

核心变化：玩家的主目标从「赢钱」变成「场子活下去、活得好」。赌桌从"全部玩法"降级为"玩法之一"。

## 二、新核心循环（昼夜双相，demo 期简化为局内相位）

```
┌─ 营业相位（现有赌桌原样嵌入）─────────────────┐
│  客流进场 → 每局结算 → 概率触发事件（客人闹事）  │
│  玩家选择：亲自下场（现有交互）/ 观察（看客人赌） │
└──────────────────────┬───────────────────────┘
                       ↓ 打烊（当日 N 局后）
┌─ 打烊相位（新面板）──────────────────────────┐
│  当日账本（各桌盈亏/事件损失/客单）              │
│  口碑结算（客流预期升降）                        │
│  有限行动点：调配赔率 / 修设施 / 与 Eidos 互动    │
└──────────────────────┬───────────────────────┘
                       ↓ 次日
                  口碑 → 客流 → 营收（飞轮）
```

不依赖真实时间：一个「营业日」= 固定局数（建议 8-12 局），打完进打烊面板。
参照系：夜雀食堂的昼夜双相；火山的女儿的日程条（打烊行动点即最小日程系统）。

## 三、店主系统四模块（二期内容，一期只搭骨架）

| 模块 | 字段/机制 | 与现有资产的接线 |
|---|---|---|
| 客流 traffic | 口碑(0-100) → 每局进店客人数 → 被动营收 | 新字段；事件后果写口碑 |
| 赔率调配 rake | 对 Eidos 公平赔率表的附加抽水 0–8%；抽水↑营收↑口碑↓ | **直接复用赌场数值成果**：公平赔率表是基准线，调配是经营杠杆 |
| 设施 tables | 五桌各自 耐久/开放状态；损坏则该桌当日歇业 | 醉汉砸场事件打耐久（现 debuff 机制扩展） |
| 看板 Eidos | 关系值 bonds.eidos → 当日 buff（客流加成/事件减免） | 现 bonds 字段原样沿用 |

## 四、现有资产重新定位表

| 资产 | 现状 | 改造后 |
|---|---|---|
| 五游戏内核（bj/roulette/slots/sicbo/baccarat） | 玩家操作 | **不动**。新增「观察模式」让客人自动赌（内核公式原样驱动） |
| `DG.casino.applyOutcome` | 玩家入账口 | 不动。店主模式下区分入账方（玩家/场子） |
| 事件系统 POOL | 「你」视角文案 | 文案微调为场子视角（如「你输了」→「这桌输了」），机制不动 |
| `casino.res.{页签id}` 分槽 | 玩家各桌战绩 | 扩展为各桌**账本**（玩家盈亏+场子盈亏） |
| desc/mood 资源 | 赌注与盈亏 | 不动。赌场营收继续走 desc（叙事资本），**不引入新货币**（见决策点 2） |
| 连输 5 局「完成」debuff | 玩家 debuff | 保留给亲自下场模式 |

## 五、数据模型改动（state.js，一期只加前三个字段）

```js
casino2: {
  phase: 'night',        // 'night' 营业 / 'prep' 打烊
  day: 1,                // 第几个营业日
  reputation: 50,        // 口碑 0-100
  traffic: 3,            // 当期客流（每局客人概数）
  rake: 0,               // 附加抽水 0-0.08（0=严守 Eidos 公平线）
  tables: {},            // { bj:{wear:0,open:true}, ... } 二期
  guests: [],            // 当期客人快照（二期）
  guestBook: {},         // 客人图鉴：见过/事件过的客人（二期）
  ledger: []             // 每日账本 [{day, perTable, events, net}]（一期）
}
```

迁移：migrate() 缺字段补默认（与 bonds/lastEventIds 同套路，零迁移成本）。

## 六、实施阶段（每期独立可测、可交付）

| 期 | 内容 | 规模估计 | 完成判据 |
|---|---|---|---|
| **一期 视角转换** | casino2 骨架（phase/day/reputation/traffic/ledger）；营业 N 局进打烊面板（账本+口碑变化）；事件文案转场子视角；赌桌标注「可亲自下场」 | ui.js +约 250 行，新测试约 40 断言 | 冒烟+CDP 全绿；一天循环可完整走通 |
| **二期 经营层** | 客人参数模拟（traffic/reputation/rake 三数联动闭环）；赔率调配 UI；设施耐久与歇业 | 新 guest.js 内核 + ui.js +约 400 行 | 飞轮数值自洽（口碑-客流-营收 MC 验证无发散） |
| **三期 深度** | Eidos 看板 buff 实装；客人图鉴；多结局钩子；宇宙联动种子 | 待一期二期评审后定 | 剧情线第一章可接入 |

## 七、明确不做（demo 期防范围蔓延）

- 不做实时客人个体 AI（二期也是参数级模拟，客人只在事件里具象）
- 不做员工招聘（看板只有 Eidos 一人；排班系统整个后置）
- 不做真实时间昼夜（局内相位足够）
- 不引入新货币（营收走 desc）
- 不做多赌场/多宇宙连锁（留种子不做）

## 八、待用户拍板的三个决策点

1. **玩家身份设定**：A) 受 Eidos 托付的代理店主（关系线=还赌场/夺回自由）B) 玩家就是庄家本人（Eidos 是下属/旧识）。影响全部剧情文案基调。
2. **营收货币**：推荐继续走 desc/mood 不引新货币（与收容宇宙一体，省一层教学）；若想要独立「流水」货币请明说。
3. **一期范围**：A) 最小转换（视角+账本+口碑显示，无参数模拟）B) 直接含客人参数闭环（一期即二期）。推荐 A——先让「一天」的结构立起来，数值飞轮二期再收紧。
